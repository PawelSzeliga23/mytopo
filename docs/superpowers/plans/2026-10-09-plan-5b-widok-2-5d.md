# Plan 5b: widok 2.5D na stronie skały — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Przeglądarka ściany na stronie skały pokazuje domyślnie model 2.5D (skała wycięta z tła, tryb „hologram” albo „zdjęcie”, drogi i wpinki na powierzchni, wybór i podświetlanie dróg w obie strony jak w 2D), z przełącznikiem 2.5D / 2D w rogu; ściany bez gotowej głębi, zarośnięte (`show_3d = false`) albo bez WebGL pokazują 2D.

**Architecture:** API dokłada do ściany `segments_url`, `show_3d` (z `topo.depth.wants_3d`) i `vegetation_ratio`. Na froncie cała geometria to czyste funkcje w `web/src/crag/surface.ts` (dekodowanie PNG 16-bit przez `fast-png`, siatka węzłów, maska skały/podłoża, indeks trójkątów, głębia punktu jako mediana 5×5 węzłów, linie dróg w 3D) — przeniesione z przetestowanego podglądu galerii (`api/topo/depth_preview_view.html`) i pokryte testami Vitest. Komponent `Wall3D` (@react-three/fiber + drei) tylko rysuje gotową powierzchnię i linie oraz obsługuje kliknięcia/najechania. `WallViewer` wybiera tryb i ładuje `Wall3D` leniwie (`React.lazy`), więc three.js nie trafia do paczki mapy; strona skały też ładowana leniwie (konva poza paczką mapy — wniosek z planu 4).

**Tech Stack:** jak w planie 4 + nowe: `three`, `@react-three/fiber` (v9, React 19), `@react-three/drei`, `fast-png`, `@types/three`.

**Spec:** `docs/superpowers/specs/2026-10-08-topo-design.md` §6.2–6.3 (2.5D domyślnie, przełącznik na 2D, OrbitControls ±30°/±20°, przybliżanie, suwak głębi, brak WebGL lub głębi → 2D), `docs/superpowers/specs/2026-10-08-frontend-design.md` §4 (przełącznik w rogu przeglądarki), decyzje z „Wnioski z wykonania” i „Zmiana po próbie” w `docs/superpowers/plans/2026-10-08-plan-5a-mapy-glebi.md`.

## Global Constraints

- Klasy segmentacji (`segments.png`, 8-bit L): 0 inne, 1 roślinność, 2 niebo, 3 skała, 4 podłoże. Rysowane są tylko trójkąty, których wszystkie trzy węzły to skała lub podłoże. Brak `segments_url` → wszystko traktowane jak skała.
- `depth.png`: 16-bit szarość, jasne = bliżej, dłuższy bok ≤ 768 px.
- Siatka: dłuższy bok 384 oczka, krótszy proporcjonalnie; szerokość modelu 1,6 jednostki przy zdjęciu poziomym (przy pionowym wysokość 1,6).
- Hologram: skała `#9ec2db`, podłoże `#949494` (oba motywy), cieniowanie z normalnych (światło z lewej góry), poziomice głębi (40 poziomów, słabe), tło sceny = `--map-bg`. Tryb „zdjęcie”: tekstura zdjęcia (bez nakładania kolorów — to zostaje w edytorze, plan 7).
- Kamera: OrbitControls, obrót ±30° w poziomie i ±20° w pionie, przybliżanie 0,8–5, przesuwanie wyłączone; suwak „głębia” 0–0,6 szerokości (domyślnie 0,25).
- Linie dróg: kolory pasm i wyróżnienia jak w 2D (`bandColor`, wybrana pogrubiona, pozostałe przygaszone gdy wybrana jest na zdjęciu), numery jak na topo (`orderedLines`), wpinki jako kropki; głębia punktu = mediana 5×5 węzłów wokół niego (gałąź nie wyciąga linii przed ścianę).
- Przełącznik w prawym górnym rogu przeglądarki: „2.5D · 2D”; w 2.5D obok „hologram · zdjęcie”. Widoczny tylko gdy ściana ma gotową głębię (`depth_url`). Domyślnie 2.5D, gdy `show_3d` i jest WebGL.
- Wszystkie teksty po polsku.
- Testy: `cd web; npm test`, `docker compose run --rm api pytest -q`. **Zasada testów:** pisane razem z kodem, uruchamiane raz na końcu zadania.

## Review Focus

1. **Brak WebGL** (stare urządzenie, wyłączone przyspieszenie) — przeglądarka pokazuje 2D bez błędu, przełącznik 2.5D niedostępny — Task 4 `WallViewer.test.tsx`.
2. **Głębia lub segmentacja nie wczyta się (404, uszkodzony PNG)** — automatyczny powrót do 2D z komunikatem zamiast pustego płótna — Task 3/4 (`onFail` → 2D).
3. **Ściana zarośnięta (`show_3d = false`) z gotową głębią** — domyślnie 2D, ale przełącznik pozwala obejrzeć 2.5D — Task 4.
4. **Punkt linii poza zdjęciem albo linia z jednym punktem** — brak wyjątku, linia pominięta lub przycięta do krawędzi — Task 2 `surface.test.ts`.
5. **Zdjęcie pionowe** (wysokość > szerokość) — siatka i proporcje poprawne — Task 2 `surface.test.ts`.

### Task 1: API — `segments_url`, `show_3d`, `vegetation_ratio`

**Files:** Modify `api/topo/schemas.py` (`WallOut`), `api/topo/api/crags.py` (`_wall_out`); Test `api/tests/test_api_crags.py`.

- `segments_url = media_url("walls/{id}/segments.png")` gdy `wall.vegetation_ratio is not None` i `depth_status == "ready"`, inaczej `None`.

- Commit: `feat: API ściany — segmentacja i decyzja 2.5D`.

### Task 2: Geometria powierzchni (`web/src/crag/surface.ts`)

**Files:** Create `web/src/crag/surface.ts`, `web/src/crag/surface.test.ts`; Modify `web/package.json` (+ `fast-png`, `three`, `@react-three/fiber`, `@react-three/drei`, `@types/three`), `web/src/lib/api.ts` (`WallOut` + `segments_url: string | null`, `show_3d: boolean`, `vegetation_ratio: number | null`).

**Interfaces (Produces):**
- `decodeDepth(buffer: ArrayBuffer): Raster` — `Raster = { width: number; height: number; data: Float32Array }` w zakresie 0–1 (16-bit /65535, 8-bit /255; kanał 0 przy obrazach wielokanałowych).
- `decodeClasses(buffer: ArrayBuffer, width: number, height: number): Uint8Array` — najbliższy piksel, gdy rozmiar inny niż głębi.
- `ROCK = 3`, `GROUND = 4`, `GRID_LONG_SIDE = 384`.
- `gridSize(width, height): { gx: number; gy: number }`; `modelSize(width, height): { width: number; height: number }` (dłuższy bok 1,6).
- `buildSurface(depth: Raster, classes: Uint8Array | null): Surface` — `Surface = { gx, gy, width, height, depth: Float32Array /*węzły*/, cls: Float32Array, positionsXY: Float32Array /*x,y na węzeł*/, uvs: Float32Array, index: Uint32Array /*tylko trójkąty skały/podłoża*/ }`.
- `surfaceDepthAt(surface, x: number, y: number): number` — mediana 5×5 węzłów, x/y w 0–1, przycinane do krawędzi.
- `linePoints3D(points: {x:number;y:number}[], surface, scale: number, step = 6): number[]` — płaska lista x,y,z co ~`step` px zdjęcia głębi, z = (głębia − 0,5)·scale + 0,004·szerokość; < 2 punkty → `[]`.
- Testy: rozmiary siatki dla poziomego i pionowego; indeks pomija trójkąty z węzłem nieba/roślinności i zawiera pełną siatkę bez klas; mediana ignoruje pojedynczy „wystający” węzeł; punkty poza zakresem przycięte; dekodowanie 16-bit (zakodowany przez `fast-png` `encode` w teście) i 8-bit.
- Commit: `feat: geometria powierzchni 2.5D (siatka, maska skały, linie w 3D)`.

### Task 3: Komponent `Wall3D`

**Files:** Create `web/src/crag/Wall3D.tsx`, `web/src/crag/wall3dMaterials.ts` (shadery hologramu i zdjęcia jako `THREE.ShaderMaterial`, kod jak w podglądzie galerii bez pędzli i bez nakładania kolorów).

- Props: `wall`, `routes`, `selectedRouteId`, `hoveredRouteId`, `onSelectRoute`, `onHoverRoute`, `look: "holo" | "photo"`, `depthScale: number`, `onFail: () => void`.
- Wczytuje `depth_url` i `segments_url` (`fetch` → `arrayBuffer` → `decodeDepth`/`decodeClasses`), buduje `Surface` w `useMemo`; błąd wczytania → `onFail()`.
- Scena: `<Canvas camera={{ fov: 40, position: [0, 0, 2.6] }}>`, siatka `BufferGeometry` (pozycje z `positionsXY` + z = (głębia − 0,5)·`depthScale`·szerokość, `computeVertexNormals`), materiał wg `look`; `OrbitControls` z drei z ograniczeniami z Global Constraints; linie drei `<Line>` z `linePoints3D` (kolor `bandColor`, szerokość 3 / 5 wybrana, przezroczystość 0,35 przygaszona), wpinki `<mesh>` kule; numery drei `<Html>` przy pierwszym punkcie w kółku jak w 2D (tekst `orderedLines`).
- Kliknięcie linii → `onSelectRoute(routeId)`, kliknięcie w pustą scenę → `onSelectRoute(null)`; `onPointerOver/Out` → `onHoverRoute`.
- Bez testów jednostkowych (WebGL nie działa w jsdom) — logika jest w `surface.ts`; sprawdzenie w przeglądarce w Task 5.
- Commit: `feat: widok 2.5D ściany (hologram i zdjęcie, drogi na powierzchni)`.

### Task 4: Przełącznik 2.5D / 2D i leniwe ładowanie

**Files:** Modify `web/src/crag/WallViewer.tsx`, `web/src/crag/WallViewer.test.tsx`, `web/src/App.tsx` (`CragPage` przez `React.lazy` + `Suspense` z „Wczytywanie…”); Create `web/src/lib/webgl.ts` (`hasWebGL(): boolean`, wynik zapamiętany).

- `WallViewer`: stan `mode: "3d" | "2d"` (start: `wall.depth_url && wall.show_3d && hasWebGL() ? "3d" : "2d"`), `look` („hologram” domyślnie), `depthScale` (0,25). `Wall3D` przez `React.lazy`; `onFail` → `mode = "2d"` + komunikat „Nie udało się wczytać modelu 2.5D — pokazuję zdjęcie.” na 4 s.
- Przełącznik (prawy górny róg, nad płótnem): segmenty „2.5D · 2D” gdy `depth_url && hasWebGL()`; w 2.5D dodatkowo „hologram · zdjęcie” i suwak „głębia”.
- Testy (Vitest, `Wall3D` i `hasWebGL` zamockowane): `show_3d` + WebGL → renderuje `Wall3D`; `show_3d = false` → 2D i przełącznik pozwala przejść na 2.5D; brak `depth_url` → brak przełącznika; brak WebGL → 2D bez przełącznika; `onFail` → 2D i komunikat.
- Commit: `feat: przełącznik 2.5D/2D na stronie skały i leniwe ładowanie`.
